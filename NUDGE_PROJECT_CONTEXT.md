## What is Nudge?

Nudge is a **simulated stock trading app with an AI-powered behavioural guard layer**.

It is NOT a stock price prediction engine. It does NOT tell users whether a stock is good or bad.

It detects when a **user is making an emotionally-driven, panic-based sell decision** — and intervenes with a contextual, data-grounded nudge message generated by an LLM. The user always retains final control. The nudge is advisory, never blocking.

### The core user journey

1. User opens the app and sees their simulated portfolio (pre-seeded with Indian stocks)
2. Market is down today. User panics and tries to sell Zomato.
3. Before the sell goes through, the backend intercepts the request
4. The **impulsivity engine** computes a score (0–100) from 4 behavioural signals
5. If score > 35, the **LLM caller** generates a personalised 2-sentence nudge
6. A nudge modal appears: score, message, "Hold for now" or "Sell anyway"
7. The outcome (heeded or ignored) is logged to the database
8. The **behaviour dashboard** shows the user their patterns over time

## Database Schema

### Table: `users`
```sql
id          TEXT PRIMARY KEY   -- e.g. "user_shinothomas_demo"
name        TEXT
created_at  DATETIME
```

### Table: `holdings`
```sql
id          INTEGER PRIMARY KEY AUTOINCREMENT
user_id     TEXT REFERENCES users(id)
ticker      TEXT               -- e.g. "ZOMATO"
stock_name  TEXT               -- e.g. "Zomato"
quantity    INTEGER
avg_buy_price REAL
buy_date    DATETIME
```

### Table: `sell_attempts`
```sql
id          INTEGER PRIMARY KEY AUTOINCREMENT
user_id     TEXT
ticker      TEXT
attempted_at DATETIME
nudge_fired  BOOLEAN
```

### Table: `nudges`
```sql
id           INTEGER PRIMARY KEY AUTOINCREMENT
user_id      TEXT
ticker       TEXT
score        INTEGER            -- 0–100
level        TEXT               -- "low" | "medium" | "high"
message      TEXT               -- LLM-generated text
signals_json TEXT               -- JSON blob of signal breakdown
heeded       BOOLEAN            -- NULL until user responds
created_at   DATETIME
responded_at DATETIME
```

### Table: `trades`
```sql
id           INTEGER PRIMARY KEY AUTOINCREMENT
user_id      TEXT
ticker       TEXT
action       TEXT               -- "sell"
quantity     INTEGER
price        REAL
nudge_id     INTEGER            -- FK to nudges (nullable)
heeded_nudge BOOLEAN            -- did they hold after nudge?
executed_at  DATETIME
```

**Request body:**

## Impulsivity Engine — Detailed Logic

File: `backend/impulsivity_engine.py`

This is the most important backend file. It must be clean, well-commented, and each signal must cite its behavioural science basis (these comments become interview talking points).

### Signal 1: Sell attempt frequency (max 35 points)
- Count how many sell attempts for this ticker in last 15 minutes from `sell_attempts` table
- `score = min(attempts * 12, 35)`
- Basis: Kahneman's System 1 thinking — rapid repeated impulsive actions without reflection

### Signal 2: Selling into a broad market dip (max 25 points)
- Fetch Nifty 50 (`^NSEI`) last 2 days from yfinance
- Compute today's % change
- If Nifty < -1.5%: `score = min(abs(nifty_change) * 5, 25)`
- Basis: Herding behaviour — retail investors panic-sell during market-wide corrections even when their stock is fundamentally unaffected

### Signal 3: Contradicts the 90-day trend (max 25 points)
- Fetch stock 3-month history from yfinance (`{ticker}.NS`)
- Compute 90-day return and today's change
- If 90d_return > 5% AND today_change < -2%: `score = min(90d_return * 0.8, 25)`
- Basis: Myopic loss aversion (Thaler & Benartzi 1995) — investors overweight short-term losses relative to long-term gains

### Signal 4: Very short hold duration (max 15 points)
- Look up `buy_date` from `holdings` table
- If hold_days < 14: `score = max(15 - hold_days, 0)`
- Basis: Short-termism — selling within 2 weeks is almost always reactive, not strategic, for retail investors

### Score interpretation
| Score | Level | Action |
|---|---|---|
| 0–34 | low | Let trade proceed, no nudge |
| 35–64 | medium | Fire nudge with moderate tone |
| 65–100 | high | Fire nudge with stronger context |

## LLM Prompt Design

File: `backend/llm_caller.py`

### System prompt (final version)
```
You are Nudge, a calm, non-judgmental financial coach for first-time Indian retail investors.
Your only job is to surface facts the user might be overlooking in a moment of stress.

Rules:
- Exactly 2 sentences. No more, no less.
- Never tell them what to DO — only surface what to CONSIDER
- Use plain conversational English; light Hinglish is acceptable if it sounds natural
- Never mention a "score", "algorithm", or "system"
- Every sentence must be grounded in the data you are given — no generic advice
- Tone: warm peer-to-peer, like a friend who happens to know markets
- Never use the words: "however", "nevertheless", "it is important to note"
```

### User message template
```
Stock: {stock_name} ({ticker})
Today's move: {today_change_pct}%
90-day return: {trend_90d_pct}%
Nifty today: {market_change_pct}%
Hold duration: {hold_days} days
Signals that fired: {signals_fired}
Impulsivity level: {level}

Generate a 2-sentence nudge for this investor who is about to sell.
```

### Model
Always use `claude-sonnet-4-20250514`. Max tokens: 150.

### Prompt iteration log
Maintain `docs/prompts/` with v1, v2, v3 versions and a note on what was wrong with each. This is important for demonstrating prompt engineering maturity to interviewers.

## Frontend Screens

### Screen 1: Portfolio (`/`)
- Header: "Good morning, Shino" + total portfolio value
- Market alert banner if Nifty is down > 1.5% (red) or up > 1% (green)
- List of holdings: stock name, quantity, avg buy price, current price, today % change badge, total value
- Tapping any holding navigates to sell confirmation

### Screen 2: Sell Confirmation (`/sell/:ticker`)
- Stock name + today's change
- Estimated P&L if sold now
- "Sell now" button → calls `POST /api/sell-intent`
- Back button

### Screen 3: Nudge Modal (overlay on sell confirmation)
- Shown only when `action === "nudge"` in response
- Impulsivity score with coloured progress bar (green < 35, amber < 65, red >= 65)
- "Before you sell..." heading
- LLM-generated message
- Signal breakdown: small pills showing what fired
- Social proof: "X% of users who held recovered within Y days" (hardcoded for demo)
- Two buttons: "Sell anyway" (calls nudge-outcome heeded=false, then execute-sell) and "Hold for now" (calls nudge-outcome heeded=true)

### Screen 4: Behaviour Dashboard (`/dashboard`)
- 3 metric cards: Nudges received / Heeded / Estimated loss avoided
- Bar chart (Recharts): nudges per week
- Pattern badges: Panic selling / FOMO buying / Improving
- Recent nudge history list

## What This Project is NOT

Do not build any of the following — they are out of scope:

- Real money trading or brokerage integration
- Stock price prediction or "buy" recommendations
- User authentication / login (use the hardcoded demo user)
- Mobile app (web only)
- Real-time WebSocket price streaming (polling every 30s is fine)
- ML model training (the impulsivity engine is rule-based, intentionally)

## Deployment

### Local development
```bash
# Backend
cd backend
pip install -r requirements.txt
python seed.py          # seed demo data
uvicorn main:app --reload --port 8000

# Frontend
cd frontend
npm install
npm run dev             # runs on localhost:5173
```

### Production
- **Backend** → Render.com (free tier). Start command: `uvicorn main:app --host 0.0.0.0 --port $PORT`
- **Frontend** → Vercel. Set env var `VITE_API_URL` to the Render backend URL.
- **Database** → SQLite on Render disk (simple) OR Supabase free tier Postgres (better for resume)

Note: Render free tier spins down after 15 min idle. First request after idle takes ~30s. Document this in README as a known limitation.

## Interview Talking Points Built Into This Project

Every design decision has a defensible answer:

| Question | Answer |
|---|---|
| "Why rule-based and not ML?" | No labelled training data available; rules are interpretable and auditable — important for SEBI compliance |
| "Why 35 as the nudge threshold?" | Hypothesis based on signal weights; would A/B test with real users to calibrate |
| "What if the nudge is wrong?" | User always retains control; nudge is advisory by design — autonomy is a core product value |
| "How does this comply with SEBI?" | No financial advice given, only factual context; `nudges` table acts as an audit log |
| "Why Claude over GPT?" | Claude's system prompt adherence and instruction-following is stronger for constrained outputs like 2-sentence nudges |
| "What's your success metric?" | Nudge heed rate + estimated loss avoided (both tracked in DB via nudge-outcome endpoint) |
